The Transformer, from scratch

Chapter 1 treated "many layers" as a black box. Now we open it. You'll build the actual architecture behind every modern model — the residual stream, attention, MLPs, and the glue — and see why each piece is exactly where interpretability reaches in.

Prerequisite check

You should be comfortable with the dot product as similarity, and reading f(Wx+b). If not, revisit Chapter 1 Parts 1–2 first — this chapter leans on both constantly.

OrientationSlide 02

Where Chapter 1 left off — and the gap it left

We ended with: text → tokens → embeddings → many layers → logits → next token. Everything except "many layers" is now concrete. But a plain stack of f(Wx+b) layers has a fatal limitation for language.

The missing ingredient

A plain feedforward network processes each position independently. But "it" in a sentence depends on what came earlier; "Paris" as an answer depends on the question. Language is about relationships between positions. The plain stack has no way for one token to look at another.

The transformer's central invention is a mechanism — attention — that lets positions read from each other. Everything else (the residual stream, MLPs, norms) is scaffolding that makes attention work at scale and depth.

Part 1 · Setup & the residual streamSlide 04

From one vector to a sequence of vectors

In Chapter 1 the model saw one input vector at a time. A transformer sees a whole sequence at once: one embedding vector per token.

So the working object is a grid: rows = positions (tokens), columns = the vector dimensions. If the text is 10 tokens and the model dimension is d = 4096, that's a 10 × 4096 array of activations.

Key vocabulary

The model dimension is written d_model (or just d). Each token gets its own d-dimensional vector that will be updated as it flows through the layers. Think of one vector per token travelling down the model in parallel.

one vector per token
Part 1 · Setup & the residual streamSlide 05

Order matters: positional information

There's a subtlety: the core attention operation is order-blind — by itself it treats the tokens as a bag, so "dog bites man" and "man bites dog" would look identical. That's clearly wrong for language.

The fix

Inject position into the vectors. Classic transformers add a positional encoding vector to each token's embedding, so position 1 gets a different nudge than position 2. Modern models often use rotary embeddings (RoPE), which rotate the query/key vectors by an angle that depends on position — encoding relative distance directly into the attention step.

The takeaway isn't the specific scheme; it's that "where a token is" is baked into its vector, so the model can use word order. When you later see position-dependent behaviour in a model, this is the root.

Part 1 · Setup & the residual streamSlide 06

The residual stream: the central object

Here is the single most important idea in the whole architecture — and the one Neel's field is built around.

Each token has a vector that runs straight through the entire model, from embedding to the final layer. This running vector is the residual stream. Every component (attention, MLP) reads from it and adds its output back into it.

The highway metaphor

Picture a highway carrying each token's vector. Components are on-ramps: they look at the traffic, compute something, and merge their result in by addition. Nothing is overwritten — contributions accumulate.

read → compute → add back
Part 1 · Setup & the residual streamSlide 07

Why "add back" is a gift to interpretability

The residual stream is a sum. The final vector is the embedding plus every component's contribution:

\[ \text{final} = \text{embed} + \sum_{\text{layers}} \big(\text{attn}_\ell + \text{mlp}_\ell\big) \]

Because it's a sum, you can ask of the final answer: "how much did this particular attention head contribute?" — and just read off its term. Contributions are separable.

This unlocks whole techniques

Direct logit attribution (Chapter 4) is exactly this: decompose the output into per-component pieces and see who pushed for which token. The logit lens works because you can take a partial sum (the stream halfway through) and interpret it. Additivity = readability. Remember this — it recurs everywhere.

Small caveat

Layer norm (slide 25) bends this slightly, and attention's softmax is nonlinear internally. But the residual stream's additive skeleton survives, and that's what the tools exploit.

Part 1 · Setup & the residual streamSlide 08

The repeating unit: a transformer block

A transformer is the same block stacked many times (12, 32, 80+). Each block does two things, in order, each adding into the residual stream:

  1. Attention — lets each token gather information from other tokens (mixes across positions).
  2. MLP — processes each token's vector on its own (works within a position).
The division of labour (hold onto this)

Attention moves information between positions. MLPs think about the information at each position. Almost every mechanistic story you'll read is some interplay of these two roles. It's a genuinely useful lens.

We'll now build each piece. Attention first — it's the heart of the thing, and the part worth the most time.

Part 2 · AttentionSlide 09

The problem attention solves

Consider: "The cat sat on the mat because it was tired." To process "it," the model must look back and pull information from "cat." That's an information-routing problem: which earlier position should this position read from, and what should it grab?

Attention in one sentence

For each token, attention decides which other tokens to look at (how much to attend), and then copies a blend of their information into the current position. It's a learned, content-dependent lookup.

The elegant part: this "who to look at" is computed with — you guessed it — dot products. The same similarity operation from Chapter 1 does the routing.

Part 2 · AttentionSlide 10

Query, Key, Value — the library metaphor

Attention borrows the vocabulary of a database lookup. Each token produces three vectors:

  • Query (Q) — "what am I looking for?"
  • Key (K) — "what do I offer / what am I about?"
  • Value (V) — "the actual content I'll hand over if you pick me."

A token's query is compared against every token's key. Good matches (high dot product) get high attention; then the current token receives a weighted blend of the matched tokens' values.

The library

You walk in with a question (query). Each book has a label (key). You compare your question to the labels, pull mainly the well-matching books, and read their contents (values). "It" queries for "the noun I refer to"; "cat" has a matching key; so "it" reads cat's value.

Part 2 · AttentionSlide 11

Q, K, V are just learned matrices

Where do these three vectors come from? Each is the token's residual-stream vector x hit with its own learned weight matrix — a plain matrix-vector multiply (Chapter 1, slide 14):

\[ \mathbf{q}=W_Q\,\mathbf{x}, \qquad \mathbf{k}=W_K\,\mathbf{x}, \qquad \mathbf{v}=W_V\,\mathbf{x} \]

W_Q, W_K, W_V are learned during training. They are the parameters of an attention head — they define what this head looks for, what it advertises, and what it moves.

Reframe

"An attention head learns to do X" cashes out as: these three matrices took on values such that queries and keys line up in situation X, and the value matrix carries the right content. Interpreting a head = understanding these matrices.

Part 2 · AttentionSlide 12

Attention scores = query · key

To decide how much token i should attend to token j, take the dot product of i's query with j's key:

\[ \text{score}_{ij} = \mathbf{q}_i \cdot \mathbf{k}_j \]

Big score → strong match → "look here." This is literally the "dot product = similarity" idea from Chapter 1, slide 11, doing the routing.

Do this for every pair and you get a grid of scores: the attention pattern, one row per querying token, one column per attended-to token.

a learned attention pattern
Part 2 · AttentionSlide 13

Turning scores into weights (softmax again)

Raw scores are arbitrary numbers. We convert each query's row of scores into attention weights that are positive and sum to 1 — using softmax, exactly as in Chapter 1, slide 29.

\[ \text{weights}_i = \text{softmax}\big(\text{score}_{i,1},\,\text{score}_{i,2},\,\dots\big) \]

Now token i has a set of weights like [0.05, 0.80, 0.15] — "spend 80% of my attention on token 2." Softmax makes attention a soft, differentiable "mostly look here, a bit there."

Why "soft"

Unlike a hard database lookup that picks one entry, softmax blends. This softness is what lets the model be trained by gradient descent — you can nudge attention continuously. It's also why a token usually attends to several places at once.

Part 2 · AttentionSlide 14

Collecting the values

Finally, token i's attention output is the weighted sum of everyone's value vectors, using those softmax weights:

\[ \text{output}_i = \sum_j \text{weight}_{ij}\,\mathbf{v}_j \]

If "it" put 80% weight on "cat," its output is mostly cat's value vector — cat's information has been copied into the "it" position. That copied information then gets added into "it"'s residual stream.

The full loop, in words

Make queries/keys/values → score every pair by dot product → softmax into weights → weighted-sum the values → add the result back to the residual stream. Three of those five steps are operations you already owned from Chapter 1.

Part 2 · AttentionSlide 15

The attention formula, decoded

Stacking all tokens' queries into a matrix Q (and likewise K, V), the entire operation is the famous one line:

Scaled dot-product attention\[ \text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V \]

You can now read arguably the most cited formula in modern AI, and say what each symbol physically does. That's a real milestone.

Part 2 · AttentionSlide 16

Why divide by √dₖ?

Dot products of long vectors tend to be large (you're summing many products). If the scores are huge, softmax becomes razor-sharp — it puts essentially all weight on one token and near-zero elsewhere.

That's bad for training: a near-flat gradient means the model can barely learn to adjust attention. Dividing by √dₖ (the square root of the key dimension) keeps scores in a sane range so softmax stays usefully soft.

Don't over-index on it

This is an engineering detail, not a deep principle. Mentioned because you'll see the √dₖ in the formula and wonder. It exists to keep the softmax well-behaved. Move on.

Part 2 · AttentionSlide 17

Multi-head attention: many lookups at once

One attention pattern can only route one kind of relationship. Real models run many attention operations in parallel — heads — each with its own W_Q, W_K, W_V.

One head might track "the noun this pronoun refers to," another "the verb's subject," another "the matching bracket." Their outputs are combined and added to the residual stream.

Why heads are the unit of analysis

Each head is a small, near-independent information-router. Much of early mechanistic interpretability was reverse-engineering individual heads — because a single head is small enough to actually understand.

parallel heads, each a specialist
Part 2 · AttentionSlide 18

What heads specialise in

Researchers have found heads that reliably do specific, nameable jobs. A few classic ones:

  • Previous-token heads — attend to the token right before. Simple, but a building block.
  • Duplicate-token heads — attend to earlier copies of the current token.
  • Induction heads — the star of slide 36: they enable copying repeated patterns and underlie in-context learning.
  • Name-mover heads — in the well-studied "IOI" task, heads that move the right name to the output.
Neel's calibration for today

Painstaking single-head reverse-engineering ("circuit finding for its own sake") is no longer what he's most excited by — it's slow and often doesn't scale to what matters. But understanding that heads are interpretable specialists is foundational, and the vocabulary shows up constantly. Learn the concept; don't build your application around hand-tracing one head.

Part 2 · AttentionSlide 19

Attention is where tokens talk

Zoom out from the machinery. The one thing to remember: attention is the only place in a transformer where information moves between positions. MLPs and everything else operate on each position in isolation.

A powerful diagnostic

If a model's behaviour depends on combining information from different parts of the input ("the answer in paragraph 3 depends on a name in paragraph 1"), attention must be doing the moving. That immediately tells an investigator where to look. This "who can even talk to whom" reasoning is a staple of real interpretability work.

Part 2 · AttentionSlide 20

Causal masking: no peeking at the future

Since the model is trained to predict the next token, position i must not be allowed to attend to positions after it — otherwise it could cheat by looking at the answer.

The fix is a causal mask: before softmax, set all "future" scores to −∞ so they get zero weight. Each token can only attend to itself and earlier tokens.

Consequence

Information flows strictly left-to-right. This is why these are called decoder-only or causal transformers, the architecture behind essentially every chatbot LLM.

can only look backward
Part 3 · The MLPSlide 21

The MLP block: per-position thinking

After attention has gathered information into each position, the MLP (multilayer perceptron — Chapter 1's feedforward network) processes each token's vector independently. It's the two-layer sandwich:

\[ \text{MLP}(\mathbf{x}) = W_{\text{down}}\;\, f\!\big(W_{\text{up}}\,\mathbf{x}\big) \]

W_up expands the vector to a wider hidden layer (often 4×), a nonlinearity f bends it, and W_down compresses back to d_model. The result is added to the residual stream.

Roughly two-thirds of a transformer's parameters live in MLPs. Whatever "knowledge" and heavy processing the model does, a lot of it is here.

Part 3 · The MLPSlide 22

What MLPs do: key–value memory

A useful mental model: each MLP neuron is a key–value memory. The W_up row is a key (a pattern it detects via dot product); if the input matches, the neuron fires, and its W_down column is the value it writes into the residual stream.

So MLPs can act like lookup tables: "if the context is about France and asks for a capital, write the Paris direction." Evidence suggests many facts are stored in MLP layers this way.

Detect → write

It's the same detect-then-act structure as a Chapter-1 neuron, now embedded in the stream. W_up row = "what fires me"; W_down column = "what I contribute." Understanding an MLP feature means reading both halves.

Part 3 · The MLPSlide 23

Neurons, features, and a warning

It would be lovely if each MLP neuron corresponded to one clean human concept. Sometimes they do ("this neuron fires on French text"). Often they don't.

Polysemanticity — the recurring headache

Most neurons are polysemantic: a single neuron fires for several unrelated concepts (e.g. "academic citations," "DNA sequences," and "HTTP requests"). This is because models pack more features than they have neurons — the superposition problem, which gets its own treatment in Chapter 3.

Polysemanticity is the reason you can't just read a model neuron-by-neuron, and the motivation for sparse autoencoders (Chapter 5). File it away; it's central.

Part 3 · The MLPSlide 24

Width, and where the parameters go

The hidden width of the MLP is typically 4 × d_model. For d = 4096, that's a 16384-wide hidden layer — lots of neurons per block.

That extra room is where the model has space to represent many features. But since it's still fewer slots than the number of things the model wants to track over all of language, superposition kicks in.

A note on modern variants

Many current models use a "gated" MLP (SwiGLU) — a small tweak with an extra gating multiply. And Mixture-of-Experts (MoE) models have many MLPs ("experts") and route each token to a few. Different plumbing, same role: per-position feature processing.

Part 4 · The glueSlide 25

Layer normalisation

Before each attention and MLP block, the input vector is normalised — rescaled so its values have a consistent size. This is layer norm (LN), or its cousin RMSNorm.

Why: without it, activations can grow or shrink wildly across dozens of layers, making training unstable. LN keeps the scale in check so gradients stay healthy.

\[ \text{LN}(\mathbf{x}) = \frac{\mathbf{x}-\mu}{\sigma}\odot\gamma + \beta \]

Subtract the mean μ, divide by the standard deviation σ, then apply a learned scale γ and shift β. ⊙ is element-wise multiply.

Modern default: pre-norm

Almost all current models are pre-norm: normalise before the block, then add the block's raw output back to the un-normalised stream. This keeps the clean additive residual highway (slide 7) intact, which is exactly why the additive interpretability tricks still work.

Part 4 · The glueSlide 26

Why layer norm mildly annoys interpreters

LN divides by the vector's own scale (σ), and that scale depends on the input. So LN is a nonlinear, input-dependent operation sitting in an otherwise clean linear picture.

Practical implication

When you do careful math on the residual stream (e.g. attributing a logit to a component), LN's rescaling can slightly muddy the accounting. Researchers handle it by "folding" LN into nearby weights or treating its scale as approximately constant. You don't need the details now — just know LN is the usual asterisk on "the residual stream is purely additive."

Everything else in the block is a matrix multiply or a softmax you already understand. LN is the one piece of grit.

Part 4 · The glueSlide 27

The full block, assembled

Here is one complete pre-norm transformer block, in the order operations happen:

# x is the residual stream (one vector per token) x = x + Attention( LayerNorm(x) ) # mix across positions, add back x = x + MLP( LayerNorm(x) ) # process each position, add back

That's it. Two lines. Attention gathers, MLP processes, both merge into the stream by addition, with a normalise before each. Every frontier LLM is this, repeated.

The elegance worth appreciating

Enormous capability comes from stacking a two-line block. There's no separate "reasoning module" or "memory module" — it's all the same block learning different things at different depths. That uniformity is part of why interpretability is even tractable: understand the block, and you understand the vocabulary of the whole model.

Part 4 · The glueSlide 28

Depth: computation accumulates in the stream

Stack the block 32 or 80 times. Each token's residual vector gets progressively refined as it flows down: early layers handle surface features, middle layers build richer meaning, late layers assemble the prediction.

A loose but useful picture of the depth-wise story (varies by model):

  • Early: token identity, syntax, simple patterns.
  • Middle: entities, relationships, factual recall, "what's being talked about."
  • Late: converting understanding into a next-token decision.
Why this matters for tools

Because meaning develops with depth, interpreters ask at which layer a concept appears. The logit lens (Chapter 4) reads the stream at every layer to watch a prediction form. Probes are trained per-layer to find where information lives. "Where in depth?" is a question you'll ask constantly.

Part 5 · The endsSlide 29

The ends: embedding and unembedding

Embedding (start)

Each token ID looks up a row of the embedding matrix W_E — its starting residual vector (Chapter 1, slide 38). Plus positional info (slide 5).

Unembedding (end)

After the last block, the final residual vector is multiplied by the unembedding matrix W_U to produce one logit per vocabulary token:

\[ \text{logits} = W_U\,\mathbf{x}_{\text{final}} \]
This is a wall of dot products

W_U has one row per token — each row is that token's "direction." The logit for a token is the dot product of the final state with its direction (Chapter 1, slide 15). "How much does my final thought point toward the word Paris?" So the model's answer is literally chosen by directional similarity.

Part 5 · The endsSlide 30

Logits → probabilities → token

The tail end is pure Chapter 1: logits go through softmax to become a probability distribution over the vocabulary (slide 29), then we sample a token (slide 46), append it, and run the whole model again for the next one.

The unembedding direction is a foothold

Because a token's meaning-in-output is a fixed direction (W_U row), interpreters can take any internal vector and ask "which tokens does this point toward?" That single move — projecting an internal state onto the vocabulary directions — is the logit lens, and it's your first hands-on technique in Chapter 4. The transformer's own output mechanism doubles as an interpretability probe.

Part 6 · Interp-relevant framingsSlide 32

Framing 1: the stream as a sum of contributions

We flagged this on slide 7; now that you've seen the whole model, here's its power. Every attention head and every MLP writes an additive term into the residual stream. So the final state — and thus the logits — is a giant sum of independently-computable pieces.

This is the mechanistic superpower

You can ask counterfactual questions per component: "If head 5 in layer 9 hadn't written its contribution, would the model still say Paris?" Additivity means you can add, remove, or swap individual terms and measure the effect. That's the foundation of attribution and patching (Chapter 4).

Part 6 · Interp-relevant framingsSlide 33

Framing 2: you can read the stream at any depth

The residual stream lives in the same space from start to finish (it's always d_model-dimensional). So the unembedding trick — projecting a vector onto vocabulary directions — works on the stream at any layer, not just the end.

Preview: the logit lens

Apply the unembedding to the residual stream after layer 5, layer 10, layer 20… and you get a running readout of "what token is the model leaning toward so far." You can literally watch a prediction crystallise across depth. Because the stream is one consistent space, this just works. Chapter 4 makes it hands-on.

Part 6 · Interp-relevant framingsSlide 34

Framing 3: circuits — components composing

Components don't work alone. A head in layer 3 can write something into the stream that a head in layer 8 later reads and acts on. A connected chain of components that together implement some behaviour is a circuit.

Two ways a head "chooses"

An attention head has two logical jobs, sometimes analysed separately: the QK circuit decides where to attend (via W_Q, W_K), and the OV circuit decides what to copy once it attends (via W_V and the output matrix). This decomposition is a classic tool for understanding a head.

You don't need to compute these yet. The point: behaviours are implemented by compositions of the pieces you now understand — and finding those compositions is what "mechanistic" means.

Part 6 · Interp-relevant framingsSlide 35

Framing 4: the two-role heuristic, restated

Keep this on a sticky note

Attention moves information between token positions. MLPs transform information within a position.

When you meet a puzzling behaviour, this splits your investigation immediately:

  • Does the behaviour require combining distant parts of the input? → suspect attention, and ask which head moves what, from where to where.
  • Is it about recalling a fact or computing a feature at one spot? → suspect an MLP, and ask which neurons/features fire.

Simple, but it's genuinely how experienced researchers carve up a problem. You now have that carving knife.

Part 6 · Interp-relevant framingsSlide 36

A real discovered circuit: induction heads

The most famous concrete result in early interpretability. Give a model a pattern like …[A][B]…[A] and it predicts [B] — it copies from the earlier occurrence. This underlies a lot of in-context learning (learning from examples in the prompt).

It's implemented by a two-head circuit:

  1. A previous-token head writes "the token before me was A" into each position.
  2. An induction head at the second [A] looks for "a position whose previous token was A," finds the first [A], and copies what came after it — namely [B].
Why it's a landmark

It was mechanistically understood — not just "this head correlates with copying," but the actual algorithm, verified causally. It's the proof-of-concept that models contain real, findable circuits. It also arrives suddenly during training, coinciding with a jump in in-context learning ability.

For your taste

Understand induction heads as the canonical example. But note Neel now finds "find another circuit like this" less exciting than using this understanding for pragmatic, safety-relevant ends.

Part 6 · Interp-relevant framingsSlide 37

Composition and "virtual weights"

The induction circuit shows components reading each other's outputs. Because everything communicates through the one additive stream, an early component's output is a later component's input — you can even calculate an effective "virtual weight" connecting two components directly, by multiplying the relevant matrices.

The big idea to carry forward

A transformer is not a sequence of black boxes; it's a communication network where components write messages to the residual stream and other components read them. Interpreting the model means figuring out who is writing what for whom. Chapters 4–6 are toolkits for answering exactly that.

Part 7 · WrapSlide 38

Variants you'll hear about

decoder-only
the causal, left-to-right architecture we built. Every chat LLM (GPT, Claude, Llama, Qwen, Gemma). This is your default mental model.
encoder-only
e.g. BERT — sees the whole input at once (no causal mask), used for classification/embeddings, not generation.
RoPE
rotary positional embeddings — the common modern way to encode position (slide 5).
SwiGLU MLP
a gated MLP variant used in most current models. Same role, slightly fancier.
MoE
Mixture-of-Experts: many MLP "experts," each token routed to a few. Huge total params, cheaper compute.
GQA
grouped-query attention — heads share keys/values to save memory. A plumbing optimisation.

All of these are refinements of the same skeleton. Learn the skeleton and the variants are footnotes.

Part 7 · WrapSlide 39

Common misconceptions to drop now

  • "The model plans its whole answer." It predicts one token at a time; apparent planning is emergent from strong next-token prediction plus the context it's built so far. (Though whether models do some internal lookahead is a live research question!)
  • "Each neuron means one thing." Mostly false — polysemanticity and superposition (Ch3). This is the single most important correction.
  • "Attention weights explain the model." Attention shows where info moved, not what was moved or why. Pretty attention maps are suggestive, not proof — a classic overclaim.
  • "The chain-of-thought is the model's real reasoning." Not necessarily — CoT can be unfaithful (Ch4). Never assume the visible reasoning is the actual cause.
Neel-flavoured warning

Several of these ("attention maps explain everything," "CoT is faithful") are exactly the kind of unexamined assumption that sinks applications. Skepticism about your own interpretation is the job.
