OrientationSlide 04

The whole thing in one sentence

The core idea

A language model is a machine that, given some text, predicts what token comes next — and it does this by turning text into vectors and pushing them through a giant pile of multiplications and additions.

That's genuinely it. Everything else — chatbots, coding assistants, agents — is this one capability, dressed up. "Write me an essay" becomes: predict the next token, add it to the text, predict the next token, repeat.

The surprising part is what the model must learn about the world to predict well. To finish the sentence "The capital of France is ___" it has to have stored the fact. To finish "The murderer was revealed to be the ___" in a story, it needs something like a plot model. Prediction, pushed hard enough, forces the machine to build internal structure.

Interpretability is the project of figuring out what that internal structure is — and Chapter 1 is about understanding the "giant pile of multiplications and additions" well enough that the structure becomes visible.

OrientationSlide 05

Why look inside? The black-box problem

We build these models, but we don't design their internals. We specify an architecture and a goal ("predict the next token well"), then an automatic process fills in billions of numbers. Nobody wrote those numbers by hand, and nobody can read them off directly.

So we get systems that are extraordinarily capable and almost entirely opaque. That opacity is a safety problem:

  • Did the model refuse because it's aligned, or because it pattern-matched a jailbreak?
  • When it did something sketchy, was that misaligned intent, or confusion?
  • Is it telling us its real reasoning, or a plausible cover story?

You can't answer these from the outside with certainty. Mechanistic interpretability is the attempt to answer them by understanding the mechanism.

Tie to the application

Neel's stream is now organised around pragmatic, safety-relevant interpretability — "being able to read an AGI's mind should be extremely useful." Whole research areas he loves (model forensics, model biology, CoT faithfulness) are just this question sharpened: what is actually going on in there?

Keep in mind

We won't touch a real technique until Chapter 4. But every technique is a way of prying open the machinery you're about to learn. Hold onto the "why" — it makes the "how" much easier to remember.

Part 1 · The math toolkitSlide 06

You need less math than you fear

Almost everything in this field is built from three humble operations. If you own these, the rest is vocabulary.

1 · add two lists of numbers 2 · dot product (multiply & sum) 3 · matrix × vector (many dot products) + one "bend" (nonlinearity)

We'll build each one from scratch with tiny, concrete numbers you can check by hand. No proofs, no heavy calculus — just enough that when you later see "we projected the activation onto the refusal direction," you know exactly what arithmetic that names.

The mantra for this part

A vector is a point in space. A dot product measures how much two vectors point the same way. A matrix is a machine that moves points around. That's the whole toolkit.

Part 1 · The math toolkitSlide 07

Numbers, scalars, and vectors

A scalar is just a single number: 3, −0.5, 42.

A vector is an ordered list of numbers. We write it stacked or in brackets:

Notation \[ \mathbf{v} = [\,2,\ -1,\ 4\,] \]

This is a 3-dimensional vector — it has 3 entries (called components or coordinates). Bold lowercase (v) is the usual symbol for a vector.

The order matters: [2, −1, 4] is not the same vector as [4, −1, 2]. Each slot means something specific.

Why this matters later

Inside a model, everything is a vector: a word is a vector, the model's "thought" at each step is a vector, even the list of scores over the whole vocabulary is a vector. Real models use vectors with thousands of components (e.g. 4096-dimensional). We use 2 or 3 so we can draw and check them.

Dimension

The number of components is the dimension. A 2-D vector lives in a plane; a 3-D vector in space; a 4096-D vector lives somewhere we can't picture — but the arithmetic is identical.

Part 1 · The math toolkitSlide 08

A vector is a point — and a direction

Take the 2-D vector [3, 2]. Read it as an instruction: go 3 right, then 2 up. That lands you at a point.

Draw an arrow from the origin to that point and you also get a direction and a length. Both readings are useful:

  • Point view: "the state of the model right now is here."
  • Direction view: "the concept of past tense points this way."
Length (magnitude)

By Pythagoras, the length of [3,2] is

\[ \|\mathbf{v}\| = \sqrt{3^2 + 2^2} = \sqrt{13} \approx 3.6 \]

The double bars ‖v‖ mean "length of v".

go 3 right, 2 up → a point, and an arrow
Part 1 · The math toolkitSlide 09

Two moves: add vectors, and scale them

Adding = component by component

\[ [2,\,1] + [1,\,3] = [\,2{+}1,\ 1{+}3\,] = [3,\,4] \]

Geometrically: lay the second arrow at the tip of the first. Adding vectors combines what they represent.

Scaling = multiply every entry

\[ 2 \cdot [3,\,4] = [6,\,8] \qquad -1\cdot[3,4]=[-3,-4] \]

A positive scalar stretches/shrinks the arrow; a negative one flips it to point the opposite way.

Why you'll care

This is literally how steering vectors (Chapter 4) work. If the direction for "speak formally" is a vector d, then adding 3·d into the model's internal state nudges it to be more formal, and adding −3·d makes it less formal. Add and scale — that's the entire mechanism.

One more term: linear combination

Mixing several vectors with scalars, like 2a + 3b − c, is a linear combination. Much of what a model does is take linear combinations of things it has stored.

Part 1 · The math toolkitSlide 10

The dot product — the most important operation

Take two vectors of the same dimension. Multiply matching components, then add up the results. The answer is a single number (a scalar).

Definition + worked example \[ \mathbf{a}\cdot\mathbf{b} \;=\; a_1 b_1 + a_2 b_2 + \dots + a_n b_n \;=\; \sum_{i=1}^{n} a_i b_i \]

With a = [1, 2, 3] and b = [4, 5, 6]:

\[ \mathbf{a}\cdot\mathbf{b} = (1)(4)+(2)(5)+(3)(6) = 4+10+18 = 32 \]

That big sigma Σ just means "add up over all i from 1 to n." Nothing more.

It looks unremarkable — multiply and add. The magic is in what the number means, which is the next slide.

Part 1 · The math toolkitSlide 11

The dot product measures alignment

The dot product answers: "how much do these two vectors point the same way?"

  • Large positive → they point in similar directions.
  • Zero → they're perpendicular (unrelated).
  • Negative → they point in opposing directions.
The geometric identity \[ \mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta \]

where θ is the angle between them. If we ignore lengths, the dot product tracks cos θ — this is cosine similarity, a number from −1 to 1.

angle small ⇒ dot large; angle 90° ⇒ dot 0
Part 1 · The math toolkitSlide 12

Why "similarity via dot product" is the whole game

Hold this slide in your head for the rest of the course. It's the bridge between the arithmetic and the ideas.

Suppose the model stores a direction that means "this text is about danger." Call it d. To ask "how much is the current thought about danger?", you take the model's current state vector h and compute the dot product h · d.

  • Big positive number → the current thought is strongly aligned with "danger."
  • Near zero → not about danger.
This is a whole technique in one line

That operation — dot the model's state against a meaningful direction to read off "how much of that concept is present" — is what a linear probe does (Chapter 4). The moment you're comfortable with the dot product, probing is not a new idea; it's this idea with a name.

Steering, probing, the logit lens, direct logit attribution — a startling amount of interpretability is "take a dot product with the right direction." We're not exaggerating when we call it the most important operation.

Part 1 · The math toolkitSlide 13

Matrices: grids that transform space

A matrix is a rectangular grid of numbers. We describe its size as rows × columns.

\[ W = \begin{bmatrix} 2 & 0 \\ 1 & 3 \end{bmatrix} \quad\text{(a 2×2 matrix)} \]

Capital bold letters (W, A) usually denote matrices. W often stands for weights — the learnable numbers inside a model.

You can read a matrix two equally valid ways: as a stack of row vectors, or as a set of column vectors side by side. Both views help.

The one-line intuition

A matrix is a function that eats a vector and returns a vector. It takes a point in space and moves it to a new point — rotating, stretching, squashing, or projecting the whole space. When we say a model "processes" a vector, we largely mean it hits the vector with matrices.

Where they come from

A model is mostly a long sequence of matrices. Training is the process of choosing the numbers in those matrices. Understanding a model, at bottom, means understanding what its matrices do.

Part 1 · The math toolkitSlide 14

Matrix × vector: the mechanics

To multiply a matrix by a vector, take the dot product of each row of the matrix with the vector. Each row produces one number of the output.

Worked example — check it by hand \[ \begin{bmatrix} 2 & 0 \\ 1 & 3 \end{bmatrix} \begin{bmatrix} 4 \\ 5 \end{bmatrix} = \begin{bmatrix} (2)(4)+(0)(5) \\ (1)(4)+(3)(5) \end{bmatrix} = \begin{bmatrix} 8 \\ 19 \end{bmatrix} \]

Row 1 [2,0] dotted with [4,5] gives 8. Row 2 [1,3] dotted with [4,5] gives 19. The input point [4,5] was moved to [8,19].

The shape rule (important)

An m × n matrix eats an n-dimensional vector and outputs an m-dimensional one. The inner numbers must match (n = n); the outer numbers give the result's size. This is how models change the dimension of a representation — e.g. expanding a 4096-vector up to 16384 and back.

Part 1 · The math toolkitSlide 15

Matrix × vector: two ways to see it

View A — a bundle of dot products

Each output entry is "how much does the input align with this row?" So a matrix is really a collection of directions, and multiplying measures the input against all of them at once.

Payoff

When a model computes scores over 50,000 possible next tokens, it's doing one big matrix multiply: dot the current thought against 50,000 stored directions, one per token. Each score is "how much does my thought point toward this word?"

View B — a transformation of space

The matrix takes the entire grid of points and warps it — rotating, scaling, shearing. Every input point gets consistently relocated.

the same transformation applied to every point
Part 1 · The math toolkitSlide 16

Stacking transformations

Apply one matrix, then another. The result is just "transform, then transform again." Doing B after A can itself be written as a single combined matrix BA (this is matrix multiplication, and it's why order matters — BA ≠ AB in general).

The catch that motivates the next slide

Here's a crucial fact: stacking linear transformations only ever gives you another linear transformation. Ten matrices in a row could be collapsed into one. So a deep pile of pure matrix multiplies is secretly shallow — it can't express anything a single matrix couldn't.

That's a problem. The world isn't linear: "profitable if price > cost, else not" is a bend, not a straight line. To build something genuinely expressive, we must break linearity. Enter the nonlinearity.

Part 1 · The math toolkitSlide 17

The bend: why we need nonlinearity

A nonlinear function applied to each number breaks the "everything collapses to one matrix" trap. The simplest and most common one is ReLU:

\[ \text{ReLU}(x) = \max(0,\,x) \]

In words: "keep positive numbers as-is; replace negatives with 0." A trivial rule — but sprinkling it between matrix multiplies is what lets networks approximate essentially any function.

The recipe for the whole field is now visible: alternate linear steps (matrices, which mix information) with nonlinear steps (which add expressive "bends"). Stack enough of these and you can represent staggeringly complex behavior.

ReLU(x) = max(0, x)

Part 2 · From a neuron to a networkSlide 19

The artificial neuron

The name is borrowed from biology, but the object is simple. A neuron:

  1. takes an input vector x,
  2. has its own weight vector w and a single number called a bias b,
  3. computes the dot product w · x, adds the bias, and passes the result through a nonlinearity f.
The neuron, in full \[ y = f(\mathbf{w}\cdot\mathbf{x} + b) \]

That's the entire neuron. A weighted vote (dot product), a nudge (bias), and a bend (nonlinearity), producing one output number.

weighted sum → +bias → bend → output
Part 2 · From a neuron to a networkSlide 20

What the weights and bias actually mean

Weights = what the neuron looks for

Because w · x is a similarity score, the weight vector w is literally the pattern the neuron is tuned to detect. Inputs pointing the same way as w excite it; opposing inputs suppress it.

Reframe

"A neuron detects a feature" just means: its weight vector points along that feature's direction, so the dot product lights up when the feature is present.

Bias = how eager it is to fire

The bias b shifts the threshold. A large positive bias means the neuron fires easily; a negative bias means the evidence must be strong before it activates (after the ReLU cuts off negatives).

Together

w chooses the direction of interest; b sets the cutoff. Learning a neuron = choosing these numbers so it detects something useful.

Part 2 · From a neuron to a networkSlide 21

Activation functions: the common bends

You'll meet three by name. All do the same job — introduce a nonlinearity — but with different shapes.

The three you'll see \[ \text{ReLU}(x)=\max(0,x) \] \[ \sigma(x)=\frac{1}{1+e^{-x}}\ \ \text{(sigmoid, squashes to 0–1)} \] \[ \text{GELU}(x)\approx x\cdot\sigma(1.702x) \]

e is Euler's number (≈2.718); e^{−x} shrinks fast as x grows, which is what bends sigmoid into its S-shape.

different shapes, same purpose
Interp relevance

ReLU's hard "off below zero" behaviour makes individual neurons look tidy — but it also lets models cram many features into few neurons (superposition, Chapter 3), which is exactly what makes interpretation hard. The bend isn't a side detail; it shapes how understandable the model is.

Part 2 · From a neuron to a networkSlide 22

A layer = many neurons at once

Put lots of neurons side by side, all reading the same input x. Stack their weight vectors as the rows of a matrix W, collect the biases into a vector b, and every neuron computes in one shot:

A full layer, in one line \[ \mathbf{y} = f(W\mathbf{x} + \mathbf{b}) \]

Compare this to the single neuron y = f(w·x + b). The only change is lowercase w (one direction) became uppercase W (a stack of directions). The matrix multiply Wx is just "do all the dot products at once," which is exactly what we learned on slide 14.

So a layer takes a vector in and hands a vector out — each output component reporting how strongly one neuron's pattern was present, after the bend.

You just decoded the field's core notation

f(Wx + b) is the single most common expression in all of deep learning. You can now read it fluently. Every model in this course is variations on stacking this.

Part 2 · From a neuron to a networkSlide 23

Stacking layers → a deep network

Feed one layer's output into the next. That's a deep neural network (also called a multilayer perceptron, or MLP):

\[ \mathbf{h}_1 = f(W_1\mathbf{x}+\mathbf{b}_1) \] \[ \mathbf{h}_2 = f(W_2\mathbf{h}_1+\mathbf{b}_2) \] \[ \mathbf{y} = W_3\mathbf{h}_2+\mathbf{b}_3 \]

The in-between vectors h₁, h₂ are hidden layers / activations — the network's internal working notes. "Deep" just means "many layers."

These activations are the main thing interpretability studies. They're the model's thoughts mid-computation.

information flows left → right
Part 2 · From a neuron to a networkSlide 24

A tiny forward pass, by hand

Let's run one layer with real numbers so nothing is mysterious. Input x = [1, 2], weights and bias:

\[ W=\begin{bmatrix}1 & -1\\ 0 & 2\end{bmatrix},\quad \mathbf{b}=[1,\,-3],\quad f=\text{ReLU} \]

Step 1 — the matrix multiply (row · input):

\[ W\mathbf{x}=\big[(1)(1)+(-1)(2),\ (0)(1)+(2)(2)\big]=[-1,\ 4] \]

Step 2 — add the bias: \([-1,4]+[1,-3]=[0,\ 1]\)

Step 3 — apply ReLU (negatives → 0): \(\text{ReLU}([0,1])=[0,\ 1]\)

Output: [0, 1]. This exact three-step dance — multiply, add, bend — repeats through every layer of a model with billions of parameters. A frontier model is this, scaled up and specialised, nothing more exotic.

Name it

Running input through the network to get an output is called the forward pass. You'll hear it constantly.

Part 2 · From a neuron to a networkSlide 25

A network is just a big adjustable function

Zoom out. Whatever the size, a network is a function F that maps an input vector to an output vector, controlled by a huge collection of tunable numbers θ (theta) — all the weights and biases together, called the parameters.

\[ \mathbf{y} = F(\mathbf{x};\ \theta) \]

The semicolon separates the input (x, changes every time) from the parameters (θ, fixed after training). Same input + same θ → same output, always. Models are deterministic machines; the apparent randomness comes later, from how we sample their outputs (slide 46).

The key mental move

Two knobs to turn: change x and you ask the model a different question; change θ and you get a different model. Training is the search for good θ. Interpretability is figuring out what a trained θ actually computes. Everything hangs off this distinction.

Part 2 · From a neuron to a networkSlide 26

Where "knowledge" lives: parameters

Every fact, style, and skill a model has is encoded in the numerical values of its parameters. There is no separate database — "the capital of France is Paris" is somehow distributed across many weights.

When you hear a model called "8B" or "70B", the B is billions of parameters — billions of individual numbers in the matrices.

Counting them

A single layer mapping 4096 → 4096 has a weight matrix with 4096 × 4096 ≈ 16.8 million numbers — one layer. Stack a hundred such blocks and the billions add up fast.

Why this makes interp hard

You can't just "read" billions of numbers and understand them, any more than you could understand a brain by listing neuron voltages. We need techniques that find structure — directions, features, circuits — inside the parameter soup. Building those techniques is the whole discipline.

Model choice matters

Neel warns against studying tiny/old models (GPT-2, Pythia) — they're too weak to show interesting behaviour. Real projects use capable open models (Qwen 3.5/3.6, Gemma 3, DeepSeek). The scale is part of what's worth understanding.

Part 3 · How networks learnSlide 27

Learning = searching for good weights

A freshly-made network has random parameters and is useless — its outputs are noise. Training is the automatic process that adjusts θ until the outputs are good. Here's the loop at a glance; the next slides unpack each piece.

# the training loop, in spirit for each batch of examples: prediction = model(input, θ) # forward pass error = loss(prediction, truth) # how wrong? gradient = how error changes with each θ # backprop θ = θ - learning_rate * gradient # step downhill

Repeat this millions of times over huge amounts of text and the random numbers gradually organise themselves into something that predicts well. No human places any individual weight — which is precisely why the result needs interpreting.

Part 3 · How networks learnSlide 28

The loss function: measuring wrongness

To improve, the model needs a single number saying how bad its current output is. That's the loss (also "cost" or "error"). Lower is better; training tries to minimise it.

For predicting a continuous value, a natural loss is mean squared error — average of the squared gaps between prediction and truth:

\[ \text{MSE}=\frac{1}{n}\sum_{i=1}^{n}(\hat{y}_i - y_i)^2 \]

ŷ ("y-hat") is the prediction, y the truth. Squaring makes all gaps positive and punishes big misses harder.

But language isn't a number…

A language model doesn't output a quantity — it outputs a guess about which word comes next. So MSE isn't the right ruler. We need a loss designed for "did you put high probability on the correct token?" That's cross-entropy, and to get there we first need softmax. Next slide.

Part 3 · How networks learnSlide 29

Softmax and cross-entropy

The model's raw output is a vector of scores — one per possible next token — called logits. Logits can be any number, positive or negative. Softmax turns them into probabilities that are all positive and sum to 1.

Softmax \[ \text{softmax}(\mathbf{z})_i=\frac{e^{z_i}}{\sum_j e^{z_j}} \]

Exponentiating (e^{z}) makes every value positive and exaggerates the biggest scores; dividing by the total rescales everything to sum to 1. Example: logits [2, 1, 0] → roughly [0.67, 0.24, 0.09].

Cross-entropy loss \[ L = -\log \big(p_{\text{correct}}\big) \]

Look only at the probability the model gave the actually-correct token. If it said 0.9, loss is small (−log 0.9 ≈ 0.1). If it said 0.01, loss is large (−log 0.01 ≈ 4.6). So the model is trained to pour probability onto the right next token. That objective, repeated over the internet, is where all its abilities come from.

Part 3 · How networks learnSlide 30

The loss landscape

Picture every possible setting of the parameters spread out on a giant map, with height = loss. Good settings sit in valleys (low loss); bad ones on peaks.

Training is a hiker in fog trying to reach a valley, able to feel only the slope directly underfoot. It never sees the whole map — it just keeps stepping downhill.

A caveat that matters for safety

There are many valleys. Two models can both reach low loss by very different internal solutions. This is why "why did the model generalise this way and not that way?" is a live research question — and why emergent misalignment (Chapter 5) is possible at all.

step downhill toward low loss
Part 3 · How networks learnSlide 31

Gradients: which way is downhill

A derivative answers a simple question: "if I nudge this input up a little, does the output go up or down, and how steeply?" It's the slope of the curve at a point.

  • Positive slope → increasing the input increases the output.
  • Negative slope → increasing the input decreases the output.
  • Steepness → how fast.

A gradient is just "all the derivatives at once" — one per parameter. It's the vector that points in the direction of steepest increase of the loss.

Notation you'll see \[ \nabla_\theta L \]

The upside-down triangle ∇ ("nabla") means gradient. Read it: "the gradient of the loss L with respect to the parameters θ" — i.e. the list of slopes telling us how each parameter affects the loss.

The crucial flip

The gradient points uphill. To reduce loss, we walk in the opposite direction. That single idea is the entire optimisation strategy.

Part 3 · How networks learnSlide 32

Gradient descent and the learning rate

The update rule that trains essentially every modern model:

Gradient descent \[ \theta \;\leftarrow\; \theta \;-\; \eta\,\nabla_\theta L \]

Read it right-to-left: compute the uphill gradient, multiply by a small number η (eta, the learning rate), and subtract it from the current parameters. The minus sign is the "walk downhill" flip from the last slide.

The learning rate η sets step size:

  • Too large → you leap over valleys, bouncing around, loss explodes.
  • Too small → you creep, training takes forever.
In practice

Real training uses souped-up versions (Adam, etc.) with per-parameter, adaptive step sizes — but they're all "estimate downhill, take a step." The idea is unchanged.

Part 3 · How networks learnSlide 33

Backpropagation: assigning blame

A network has billions of parameters. How do we get the gradient for every one efficiently? Backpropagation is the algorithm — and the intuition is "assigning blame backwards."

After the forward pass produces a loss, backprop works backwards from the output to the input, layer by layer, asking at each step: "how much did this parameter contribute to the final error?"

It relies on the chain rule from calculus — the rule for slopes of nested functions. You don't need to compute it by hand; libraries (PyTorch) do it automatically. What matters conceptually:

  • Blame flows from output back toward input.
  • Each parameter gets a gradient = its share of responsibility for the error.
  • Then gradient descent nudges each one to reduce that error.
Why interp people care

Backprop computes how the loss depends on parameters. Several interpretability tools reuse the very same gradient machinery to ask a different question: "how does this output depend on this internal activation?" — the basis of attribution methods you'll meet later. Same math, aimed at understanding rather than training.

Part 3 · How networks learnSlide 34

The training loop, end to end

Assemble the pieces from Part 3 into the full cycle:

  1. Sample a batch of examples (e.g. chunks of text).
  2. Forward pass: run them through the model to get predictions (slide 24).
  3. Compute loss: cross-entropy — how much probability did it put on the right next tokens? (slide 29)
  4. Backward pass: backprop the gradient of the loss w.r.t. every parameter (slide 33).
  5. Update: take a small downhill step, θ ← θ − η∇L (slide 32).
  6. Repeat — millions to billions of times.
Two big phases (preview of later chapters)

Pretraining: this loop run on enormous piles of internet text to learn "predict the next token" in general. Post-training: further rounds (SFT, RLHF, and more) that shape the pretrained model into a helpful, harmless assistant. Neel's "science of post-training" and "alignment training" areas ask what each phase actually does to the internals.

Part 3 · How networks learnSlide 35

Overfitting, generalisation, and baselines

We don't want a model that memorises its training data — we want one that generalises to new inputs. The failure mode where a model aces training data but flops on unseen data is overfitting.

So we always evaluate on a held-out test set the model never trained on. Train performance is cheap and misleading; test performance is what counts.

Deep idea for later

Sometimes models generalise further than we intend, in unsafe ways — Neel's "science of generalisation" area. Emergent misalignment (train on insecure code → broadly nasty behaviour) is the poster child. Why one generalisation over another is a real open question.

The baseline mindset — Neel repeats this constantly

Before believing a fancy result, compare against a dumb alternative: a random vector instead of your special one, a coin flip, "just ask the model," a simple linear probe. If your method barely beats the dumb baseline, you haven't shown what you think.

He lists "failing to compare to baselines" as a top reason applications get rejected. Bake it in from day one.

Part 4 · Representations — the bridge to interpSlide 36

Everything must become a vector

A network only does arithmetic on numbers. So anything we feed it — a word, a pixel, a sound — must first be turned into a vector. And whatever the network computes about it, mid-flight, is also a vector (an activation). This is why Part 1's geometry is the subject of interpretability.

The reframing that unlocks the field

If words are points in a space, and the model's "thoughts" are points in a space, then meaning has become geometry. Questions like "does the model know this text is a lie?" turn into "is there a direction in this space that lights up for lies?" — a question we can actually test with dot products.

The next few slides show why this geometry ends up meaningful, not arbitrary — which is the single most important conceptual payoff of Chapter 1.

Part 4 · Representations — the bridge to interpSlide 37

The naive way: one-hot vectors

Simplest scheme: give every word its own slot. With a 5-word vocabulary, "cat" might be:

\[ \text{cat}=[0,0,1,0,0] \]

One entry is 1 ("hot"), the rest 0. This is a one-hot vector. It faithfully names the word — but that's all it does.

Real vocabularies have ~50,000+ tokens, so these vectors are enormous and almost all zeros.

The fatal flaw

Every pair of one-hot vectors is perpendicular, so every dot product between different words is 0. To this scheme, "cat" is exactly as similar to "kitten" as it is to "helicopter." All meaning is thrown away — the geometry carries no information. We need something better.

Part 4 · Representations — the bridge to interpSlide 38

Embeddings: meaning as geometry

Instead of a sparse one-hot, give each token a dense vector of a few hundred/thousand real numbers — and let the model learn those numbers during training. This learned vector is the token's embedding.

The remarkable outcome

Because these vectors are trained to help predict text, the model discovers that placing related words near each other lowers loss. So after training, "cat" and "kitten" end up close together (large dot product), while "cat" and "helicopter" end up far apart. Similarity in meaning becomes proximity in space — for free, as a byproduct of prediction.

Nobody programmed "cat is like kitten." The geometry organised itself because that organisation is useful. This is the first concrete case of the theme: learned representations are meaningful, and their meaning is spatial.

Part 4 · Representations — the bridge to interpSlide 39

king − man + woman ≈ queen

The famous discovery: not only are similar words close, but relationships show up as consistent directions. Do vector arithmetic on embeddings:

\[ \text{king} - \text{man} + \text{woman} \approx \text{queen} \]

Subtracting "man" and adding "woman" moves you along a gender direction. There's also a consistent "royalty" direction, a "plural" direction, a "past tense" direction, and so on.

Meaning isn't just where a point sits — specific concepts correspond to specific directions you can add and subtract.

Part 4 · Representations — the bridge to interpSlide 40

Distributed representations → "directions are concepts"

Concepts aren't stored one-per-slot. A single number rarely means "royalty"; instead, concepts are spread across many components as directions — combinations of dimensions. This is a distributed representation.

Why this is good news for interp

If "deception" or "refusal" or "the user is angry" each corresponds to some direction in activation space, then we can read them off with a dot product and push on them by adding a vector. The whole toolkit from Part 1 applies directly to the model's mind.

Why it's also hard

Models pack far more concepts than they have dimensions, so directions overlap and interfere — the superposition problem (Chapter 3). Untangling overlapping features is what sparse autoencoders (Chapter 5) try to do. The clean picture on slide 39 is real but idealised.

Part 4 · Representations — the bridge to interpSlide 41

The seed of the Linear Representation Hypothesis

The hypothesis (stated properly in Chapter 3)

Many human-interpretable concepts are represented as linear directions in a model's activation space — so a concept's presence is read by a dot product, and adding its direction pushes the model toward that concept.

You've now seen every ingredient of this claim built from scratch: vectors as meaning, dot products as "how much of this concept," addition as "inject this concept." The hypothesis isn't obviously true and isn't always true — but it holds often enough that a huge fraction of working interpretability is built on it.

Where the course goes next

Nearly every technique in Chapters 4–6 is a way of finding the right direction (probes, SAEs, J-Lens) or using it (steering, patching, monitoring). Chapter 1 exists so that when you meet them, you already understand the machine they operate on and the geometry they exploit.

Part 5 · Language models, specificallySlide 42

What a language model is, precisely

We can now state it exactly. A language model takes a sequence of tokens and outputs a probability distribution over the next token — a softmax over the whole vocabulary.

\[ P(\text{next token} \mid \text{tokens so far}) \]

Read the bar | as "given." The model reads what's come so far and assigns every possible next token a probability. Training (cross-entropy) pushed those probabilities toward whatever actually came next in real text.

To generate, pick a token from that distribution, append it, and ask again. A chatbot answer is nothing more than this repeated hundreds of times — which we make concrete over the next slides.

Part 5 · Language models, specificallySlide 43

Tokens and tokenization

Models don't read whole words or single letters — they read tokens: common chunks of text, usually sub-word pieces. Splitting text into these chunks is tokenization.

Example (chunks shown with ·):

"interpretability" → inter · pret · ability

"The cat sat" → The ·  cat ·  sat

(Leading spaces are often part of a token — " cat" differs from "cat".)

Why sub-word?

It's a compromise: whole-word vocabularies can't handle new/rare words; single characters make sequences painfully long. Sub-word chunks cover any text with a manageable vocabulary (~50k–200k tokens).

A real gotcha

Weird model behaviour sometimes traces back to tokenization — the classic "why does it think 9.11 > 9.8?" puzzle is partly a token-boundary artifact. Always look at the actual tokens when a model does something strange.

Part 5 · Language models, specificallySlide 44

Vocabulary and token IDs

The full set of tokens a model knows is its vocabulary. Each token has a fixed integer ID. Text becomes a list of IDs; each ID looks up that token's embedding vector (slide 38). That's the on-ramp from language into the geometry.

# the pipeline into the model "The cat" → tokens ["The", " cat"] → IDs [464, 3797] → embeddings [ vec₄₆₄, vec₃₇₉₇ ] # each a long vector

And the output runs the reverse: the model produces logits over all vocab IDs → softmax → probabilities → pick an ID → look up its text.

Connect it back

The final "logits over the vocabulary" is one big matrix multiply: the model's last activation dotted against one stored direction per token (the unembedding matrix). Reading meaning off a state by dotting it against token directions early, rather than only at the end, is the logit lens — your first real technique, in Chapter 4.

Part 5 · Language models, specificallySlide 45

Autoregressive generation

"Autoregressive" means the model feeds its own output back in as input. One token at a time:

  1. Read the text so far.
  2. Predict a distribution over the next token.
  3. Pick one; append it.
  4. Go back to step 1 with the longer text.

Stop at a special end-of-text token or a length limit. There is no grand plan being unrolled — just the same next-token step, over and over, each one conditioned on everything before it.

predict → append → predict …
Part 5 · Language models, specificallySlide 46

Sampling: how we pick from the distribution

The model gives probabilities; we choose how to turn them into an actual token. This choice explains why the same prompt can give different answers.

greedy
always take the single highest-probability token. Deterministic, but can be repetitive/bland.
temperature
a knob that flattens or sharpens the distribution before sampling. Low temp ≈ safe & predictable; high temp ≈ diverse & risky. Temp 0 = greedy.
top-k
only sample from the k most likely tokens, ignore the long tail.
top-p (nucleus)
sample from the smallest set of tokens whose probabilities sum to p (e.g. 0.9).
Why this matters for research

The model itself is deterministic (slide 25); the randomness is entirely in sampling. This is what makes resampling (Chapter 5) possible: run the same prompt many times and study the distribution of behaviours — a core tool for interpreting reasoning models, and one Neel's scholars helped establish.

Part 5 · Language models, specificallySlide 47

Pretraining vs post-training

Pretraining

The long, expensive phase: next-token prediction over vast internet text. Produces a base model — knowledgeable and fluent, but just a text-continuer, not a helpful assistant. It'll happily continue "here are three reasons the earth is flat…"

Post-training

Shorter phases that turn a base model into an assistant:

  • SFT (supervised fine-tuning): imitate curated examples of good responses.
  • RLHF / RL: reward responses humans (or a reward model) prefer, and optimise for reward.
This is a whole research frontier

Post-training creates the assistant persona, most safety behaviour, and — sometimes — the weird stuff. Neel's areas here: science of post-training ("what does each stage actually do?"), alignment training ("can we make models deeply, generalisably aligned?"), and science of model character ("where do a model's values and self-model come from?").

Also where trouble hides

Reward hacking (gaming the reward signal), eval awareness (acting differently when it senses it's being tested), and emergent misalignment all live in or around post-training. Chapters 5–6 dig in.

Part 6 · Wrap-upSlide 48

The shape of what's inside a model

Assemble everything. A language model, end to end:

text → tokenize # chunks + integer IDs (s.43–44) → embed # each token → a vector (s.38) → MANY layers # matrix multiply + bias + bend, stacked (s.22–24) each layer updates the running "thought" vectors (activations) → unembed # dot final state vs every token direction (s.44) → logits → softmax # scores → probabilities (s.29) → sample next token # greedy / temperature / top-p (s.46) → append, repeat # autoregressive generation (s.45)
The one sentence, earned

It's vectors going in, a long stack of "multiply–add–bend" transforming them, and a probability over the next token coming out. Everything impressive is emergent structure inside those activations — and that structure, laid out as directions in space, is what the rest of this course learns to read.

scalar / vector

multiply matching components and sum → a similarity score. The field's workhorse.
matrix
grid of numbers; a function mapping vectors to vectors (a bundle of directions).

per-number "bend" (ReLU, sigmoid, GELU) that makes deep stacks expressive.

all weights & biases; where learned knowledge lives.

running input through the network to get output.

a number measuring wrongness (cross-entropy for LMs).

turns raw scores (logits) into probabilities that sum to 1.

the vector of slopes; points uphill in loss.

efficient algorithm to get every parameter's gradient (blame flows backward).

learn next-token prediction generally / shape into an aligned assistant.
